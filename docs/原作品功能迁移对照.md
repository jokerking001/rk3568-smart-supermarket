### 2.1 八项能力（原：两块 ESP32-S3 即服务器）

> **飞书告警的两个方向要分清**：
> - **出站**（告警 → 飞书群）：`alert_server.c` 把消息塞进 `message_bus`，由 `feishu_bot` 走飞书 OpenAPI 发出。实测 `POST 18791/alert` 返回 `{"status":"queued"}`，说明 `MIMI_ALERT_FEISHU_CHAT_ID` 已配置。
> - **入站**（在飞书群回"接单/处理完成"→ 门店）：靠 `18790` webhook。**当前未监听**，需配置飞书 App 凭据（`MIMI_SECRET_FEISHU_APP_ID` / `APP_SECRET`）后才会起。
> - 即：**"推得出去"已通，"回得回来"待配置**。

## 3. 需要处理的 4 项

### 3.1 ⚠️ 第三个公网域名未落地

原作品：**顾客端 / 商家端 / AI 对话入口** 三个独立域名。
现状：只有 `www.mimistore.icu`（顾客端）与 `admin.mimistore.icu`（商家端，`WebServer.cpp:741` 按 Host 分流）。

**只有项目所有者能改**：Cloudflare Dashboard → Zero Trust → Networks → Tunnels → `mimistore` → Public Hostnames → 新增一条（如 `ai.mimistore.icu` → `http://10.176.240.215:8094`）。
> 另外 `www.mimistore.icu` 回源目前仍指向旧地址 `192.168.43.44`，需改成 `10.176.240.215:8094`（见 `RK3568-迁移总览.md` §15.7）。

### 3.2 ❌ Kotlin Android App 不在仓库

原作品：`Kotlin 原生外壳 + WebView + JavaScriptInterface 桥接`。
现状：纯 Web / PWA，仓库内无 `.kt` / `.apk` / `build.gradle`。

**判定**：功能上 Web 已完整覆盖（App 只是外壳）。若要"完美还原"，需重建一个 Kotlin WebView 外壳。
**默认建议**：暂不重建 —— 外壳不带来新能力，且维护成本高。

### 3.3 ❌ 低功耗 180→30 mA 已废弃

`Mode_LowPower.cpp:5` 注释：「低功耗模式 → 板子插电，已废弃」。
**判定**：**主动设计放弃，不算退化**。RK3568 典型功耗本就远高于 ESP32-S3，原低功耗叙事在新架构下不成立。
**若要保留叙事**：只能对**从机（ESP32-S3）**恢复 `Mode_LowPower`，但板子实际常供电，测不出真实收益。

### 3.4 🔁 两块自研 PCB → 主控改现成核心板

原作品：主控（ESP32-S3 核心板 V2，96.8×96.5 mm）与打印控制板均为**自研 PCB**。
现状：打印机控制板、从机（ESP32-S3）保留；**主控换成商购 ATK-DLRK3568 核心板**。

**判定**：这是"换主控"任务的必然结果，属**方案变更**而非功能缺失。

## 5. 结论

**招牌能力无退化。** 原作品最硬的四张牌 —— 多模态融合（0.78/0.22）、AI 两阶段授权、自研打印协议、语音+距离双条件唤醒 —— **全部在迁移后保持可用，且实测通过**。

未落地的三项里，**两项（第三域名、Android App）不涉及技术能力**，一项（低功耗）是架构变更后的主动放弃。**没有"迁移导致的静默功能丢失"**。

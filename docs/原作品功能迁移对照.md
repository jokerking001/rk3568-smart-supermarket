## 3. 需要处理的 4 项

### 3.1 ⚠️ 第三个公网域名 `ai.mimistore.icu` 未落地

原作品：**顾客端 / 商家端 / AI 对话入口** 三个独立域名。
现状：仓库里只找到 `www.mimistore.icu`（顾客端）与 `admin.mimistore.icu`（商家端，`WebServer.cpp:741` 按 Host 分流）。

**第三个域名是 `ai.mimistore.icu`**，证据在 **Android App** 里（`MainActivity.kt:242` 与 `:269`）：

```js
var socket = new WebSocket('wss://ai.mimistore.icu/');   // AI 对话
var recommendationWs = new WebSocket('wss://ai.mimistore.icu/');  // 个性化推荐
```

**两个客户端连 AI 的方式不一样**，这点要分清：

| 客户端 | WS 目标 | 依赖公网吗 |
|---|---|---|
| 板端顾客端网页（`web/index.html:673`） | `ws://10.176.240.100:18789/`（**内网直连 MimiClaw**） | ❌ 不依赖，局域网即可 |
| Android App（`MainActivity.kt:242/269`） | `wss://ai.mimistore.icu/`（**公网域名**） | ✅ **依赖** |

⇒ **网页版的 AI 导购现在就能用**；**App 版的 AI 导购会一直 fallback 到 `/api/customer/chat`（本地规则回答）**，直到 `ai.mimistore.icu` 配好。

**只有项目所有者能改**：Cloudflare Dashboard → Zero Trust → Networks → Tunnels → `mimistore` → Public Hostnames → 新增 `ai.mimistore.icu` → `http://10.176.240.100:18789`（注意是 MimiClaw，**不是**板端 8094）。
> 另外 `www.mimistore.icu` 回源目前仍指向旧地址 `192.168.43.44`，需改成 `10.176.240.215:8094`（见 `RK3568-迁移总览.md` §15.7）。

### 3.5 ❌ OTA 固件升级 —— 三台设备全无

原作品：ESP32-S3 主控用 **ElegantOTA**（网页界面刷固件）。迁移后**没有任何一台设备能 OTA**。

| 设备 | OTA 代码 | 分区槽 | 实际可用 |
|---|---|---|---|
| ESP32-S3 从机 | `ElegantOTA.loop()` 在 `Work7_20.ino:206` | `app0`/`app1` 双槽 | ❌ **在 `#else`（原主控）分支里，`SLAVE_MODE=1` 下不编译** |
| MimiClaw | `main/ota/ota_manager.c`（`esp_https_ota` 封装） | `ota_0`/`ota_1` 各 2 MB | ❌ **函数无任何调用点**（CLI 命令表止于 `restart`，无 OTA 命令） |
| RK3568 | 无 | — | ❌ |

**可行性**：**MimiClaw 最容易补** —— 代码在、双分区槽在、`esp_https_ota` 组件已链接，只差一个触发入口（加一条 `ota <url>` CLI 命令 ≈ 15 行）。双槽天然支持失败回滚。
从机的 ElegantOTA 依赖 `AsyncWebServer`（在 `WebServer.cpp`，`SLAVE_MODE` 下整体不编译），恢复成本较高。
RK3568 侧要新增（A/B 分区或走 SSH 部署）。

### 3.3 ❌ 低功耗 180→30 mA 已废弃

`Mode_LowPower.cpp:5` 注释：「低功耗模式 → 板子插电，已废弃」。
**判定**：**主动设计放弃，不算退化**。RK3568 典型功耗本就远高于 ESP32-S3，原低功耗叙事在新架构下不成立。
**若要保留叙事**：只能对**从机（ESP32-S3）**恢复 `Mode_LowPower`，但板子实际常供电，测不出真实收益。

### 3.4 🔁 两块自研 PCB → 主控改现成核心板

原作品：主控（ESP32-S3 核心板 V2，96.8×96.5 mm）与打印控制板均为**自研 PCB**。
现状：打印机控制板、从机（ESP32-S3）保留；**主控换成商购 ATK-DLRK3568 核心板**。

**判定**：这是"换主控"任务的必然结果，属**方案变更**而非功能缺失。

## 5. 结论

**招牌能力无退化。** 原作品最硬的四张牌 —— 多模态融合（0.78/0.22）、AI 两阶段授权、自研打印协议、语音+距离双条件唤醒 —— **全部在迁移后保持可用，且实测通过**。

需要收尾的 5 项，按"是否缺能力"分两类：

| 类别 | 项 | 说明 |
|---|---|---|
| **不缺能力，只缺配置/改动** | `ai.mimistore.icu` 域名 | App 的 AI 导购在等它；网页版不受影响 |
| | Android App 的旧 IP | 改 2 行即可 |
| | 飞书入站 webhook | 配 App 凭据即起 |
| **真缺能力** | OTA | 三台设备全无；MimiClaw 补起来最便宜 |
| | 低功耗 180→30 mA | 架构变更后的主动放弃（RK 板常供电） |

**没有"迁移导致的静默功能丢失"** —— 每一项缺失都是显式的、可追溯的。
